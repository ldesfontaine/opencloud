# openCloud v0.5.0

Depuis la [v0.4.2](v0.4.2.md). Les numéros `#…` sont ceux des tickets Forgejo.

## L'essentiel

- **Refonte UX, lots C3 à C12** (#407 à #417) : le menu suit des modules, les assistants passent en fenêtres, la vue Machines devient un arbre hôte > invités, les alertes ont une boîte de réception, la page de statut entre dans le projet.
- **Une migration de la base à quatre étapes** (`024` à `027`) : sauvegarde obligatoire avant la mise à jour.
- **Des routes d'API retirées ou renommées** (pages de statut, révocation d'un agent) : voir « Ce qui change / casse ».
- **Tests déterministes** (#425) : aucun effet pour l'opérateur.

| Quoi | Ce que ça apporte | Issue |
| --- | --- | --- |
| Modules et rôle de machine | Le menu suit les modules de l'installation ; Paramètres › Modules les liste ; une machine a un rôle (générique, Docker, Proxmox) qui fixe les modules qu'elle porte | #407 |
| Assistants Machines | Ré-enrôler, déclarer l'hôte Proxmox et attendre l'agent s'ouvrent en fenêtre | #408 |

| Alertes | Boîte de réception ; canaux et silences sous Paramètres › Notifications | #415 |

## À faire en mettant à jour

1. **Sauvegarder la base** avant de remplacer le binaire ([Mettre à jour](../installation.md#mettre-à-jour)). **Obligatoire** : une migration ne se défait pas. Le retour arrière, c'est l'ancien binaire **et** la base sauvegardée ; l'ancien binaire seul ne lit pas une base migrée.
2. **Quatre migrations**, qui s'appliquent seules au démarrage du serveur :

   | Migration | Ce qu'elle fait |
   | --- | --- |
   | `024_machine_role.sql` | Ajoute le rôle de la machine et du jeton d'enrôlement. Une machine déjà enrôlée le reçoit des faits connus : Proxmox si un hôte est déclaré ou reconnu, sinon Docker si l'agent a trouvé Docker, sinon générique |
   | `025_verb_requests.sql` | Crée les demandes de verbe à confirmation |
   | `026_machine_placement.sql` | Ajoute le type de la machine et sa correction, l'hôte désigné à la main, les cartes réseau, les disques et pools rapportés, les grappes d'hyperviseurs. Une machine déjà rapprochée d'un invité Proxmox en tire son type |
   | `027_project_publication.sql` | La publication passe dans le projet. **Une page de statut sans projet reçoit un projet**, nommé par son adresse (suffixé `-statut` ou par le début de l'identifiant si le nom est pris). Les composants saisis à la main passent côté projet |

3. **Les agents : mise à jour conseillée, rien ne casse.** Un agent en v0.4.2 ou plus ancien (v0.2.0 compris) reste connecté : le protocole ne change que par un champ ajouté, facultatif. Ce qui manque tant qu'un agent n'est pas mis à jour :

   | Ce que l'agent v0.5.0 rapporte (champ `host` du signal) | Sans lui |
   | --- | --- |
   | `virt` (réponse de `systemd-detect-virt`) | Le type de la machine reste **inconnu** (sauf correction de l'opérateur, ou invité reconnu par son hôte Proxmox) ; pas de VPS déduit |
   | Cartes réseau (nom, MAC) | Le rapprochement hôte > invités ne se fait plus **par adresse MAC** : il retombe sur le nom d'hôte, plus fragile. Corrigeable à la main (Emplacement) |
   | Disques physiques et pools (`md`, LVM, ZFS) | L'onglet stockage de la machine reste vide |

   L'agent relit ces faits au démarrage puis toutes les dix minutes, en lecture seule, sans droit à ajouter. Mettez à jour le serveur d'abord, puis les agents ([Mettre à jour](../installation.md#mettre-à-jour)).
4. **mcp-maison : v0.3.0 au minimum** (PR mcp-maison #22), d'après le ticket #431 ; ce côté n'est pas dans ce dépôt et n'a pas été vérifié ici. Raison côté openCloud : le verbe `machine.delete` répond **202** avec une demande à confirmer, et `GET /api/token/verbs` porte un champ `confirm`.
5. **Configuration (`config.toml`) : aucun changement requis.**

## Ce qui change / casse

### API

| Quoi | Avant | Maintenant |
| --- | --- | --- |
| `POST /api/machines/{id}/actions/revoke` | Révoquait l'agent | **Retirée.** `DELETE /api/machines/{id}` avec le corps `{"keep_history": true}` archive la machine (agent coupé, rien d'effacé) ; sans corps, elle est supprimée |
| `GET/POST /api/status/pages`, `GET/PUT/DELETE /api/status/pages/{id}`, `GET /api/status/pages/{id}/delete-plan` | Les pages de statut | **Retirées.** La page est la publication d'un projet : champ `publication` (`slug`, `announcement`, `language`) de `POST/PUT /api/directory/projects[/{id}]` ; `null` : projet non publié. L'adresse publique `/statut/<slug>` ne change pas |
| Composants de statut | `page_id` ; `GET /api/status/components?page=<id>` | `project_id` ; `?project=<id>`. Nouveau champ `implicit` |
| Jetons en lecture | Ouvraient `GET /api/status/pages[/{id}]` | Ouvrent `GET /api/directory/projects[/{id}]` à la place |
| `GET /api/machines`, `GET /api/machines/{id}` | — | + `role`, `modules`, `kind`, `kind_override`, `host` ; `proxmox` + `node`, `cluster`, `guest_list` |
| `GET /api/session` | — | + `roles` (rôles de machine et droits cochés d'avance) |
| `GET /api/counts` | — | + `modules` (chaque module et s'il est configuré) |
| `GET /api/token/verbs` | — | Nouveau verbe `machine.delete` ; champ `confirm` |
| Nouvelles routes | — | `PUT /api/machines/{id}/role`, `PUT /api/machines/{id}/placement`, `GET /api/machines/{id}/storage`, `GET /api/verb-requests`, `POST /api/verb-requests/{id}/actions/confirm`, `POST /api/verb-requests/{id}/actions/reject` |
| Verbe `machine.delete` pour un jeton | — | **N'exécute rien** : `202` avec `request_id`, `state`, `expires_at`. L'opérateur confirme dans l'interface, sous quinze minutes. Un jeton n'y a droit que si le verbe est coché sur lui : les jetons existants ne changent pas |

### Adresses de l'interface

| Ancienne adresse | Maintenant |
| --- | --- |
| `/cles-ssh` | Redirigée vers `/machines/acces-ssh` |
| `/page-statut/*` | Redirigée vers `/disponibilite/pages` ; les pages sont sous `/disponibilite/pages/{id}` |
| `/disponibilite/composants/{id}` | Redirigée vers la fenêtre du composant, sur la page de son projet |
| `/alertes/canaux/…`, `/alertes/silences/…` | Redirigées vers `/parametres/canaux/…`, `/parametres/silences/…` ; `/alertes/{autre onglet}` mène à `/alertes` |
| `/services/conteneurs`, `/services/annuaire` | Redirigées vers `/services` |
| `/machines/{id}/droits` | **Plus d'écran** : la fenêtre **Ré-enrôler** (`/machines/{id}/reenroller`) montre les droits à changer |
| `/machines/jeton` | **Plus de route** : le jeton s'obtient par l'assistant d'ajout et par Ré-enrôler |

Les formulaires (service, sonde, tâche, pare-feu, sauvegardes, incidents, composants) s'ouvrent en fenêtre sur leur liste, avec une adresse propre.

## Ce que ça ne fait pas

- Pas de relevé SMART : les disques sont listés, leur santé n'est pas lue.
- Les verbes à confirmation ne couvrent que la suppression ou l'archivage d'une machine.
- Une mise à jour des agents n'est pas automatique : elle se fait depuis la fiche ou à la main.
